# 2단계 판정 (skill)

언제 읽나: phase-1 통과, phase-2 미통과.

## 1. 서브에이전트로 판정한다

판정은 **새 컨텍스트의 서브에이전트**가 한다. 관찰한 세션이 자기 실행을 자기가 평가하면 빈틈을 판단으로
메운다. 서브에이전트에게는 `run-1.md` 와 샘플들의 `output.json` 을 읽히고 아래 프롬프트를 그대로 준다.

## 2. 무엇을 판정하나

「이 스킬을 무엇으로 고정할 것인가」다. 고정되는가가 아니라 **무엇으로** 고정하는가를 고른다.
`references/decision-axes.md` 의 세 결정 축(제어권·도구·환경)을 그대로 적용한다.

- `코드로 고정` — 출력 구조가 샘플마다 같고 규칙으로 쓸 수 있다. 서버 함수 하나면 끝난다
- `Claude 호출 유지` — 문장·표를 읽어 뜻을 판단해야 한다. 프롬프트·스키마·모델을 못 박는 것이 고정이다
- `고정 불가` — 시각·OCR 이 필요하거나 실행이 길어 서버리스 함수 밖이다

## 3. 게이트

```
node $SKILL_DIR/scripts/check_lite.mjs 2
```

세 절과 마지막 판정 줄을 본다. 게이트가 샘플 `output.json` 의 최상위 키 집합을 직접 비교해서 서로 다르면
`코드로 고정` 을 거부한다 — 규칙으로 쓸 수 있다는 주장이 관찰과 어긋나기 때문이다.

검사가 통과하면 학습자에게 `verdict.md` 를 보여주고 동의를 받는다. 동의하면:

```
node $SKILL_DIR/scripts/check_lite.mjs 2 --approve
```

`--approve` 없이는 통과가 기록되지 않는다. `--batch` 면 묻지 않고 넘긴다.
사람이 판정을 뒤집을 때만 `--override "<사유>"` 를 쓰고, 기록은 `Claude 호출 유지` 가 된다.

## 4. 고정 불가면

게이트가 STATUS 에 종료를 기록하고 라우팅을 출력한다. 그대로 전하고 멈춘다. 3단계 파일을 만들지 않는다.

시각·OCR 이 필요하거나 실행이 길면 이 스킬의 대상이 아니다. Agent SDK 를 Vercel 밖 컨테이너에 두거나
Managed Agents 로 가는 별도 트랙이 있고, 로컬 에이전트로 남기는 것도 답이다.
