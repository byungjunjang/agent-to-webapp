# 1단계 관찰 (skill)

언제 읽나: init 완료, phase-1 미통과.

## 1. 학습자 안내

대상 폴더에서 **그 스킬 하나만** 샘플 N건에 돌린다(N 은 STATUS 의 `samples`, 기본 5). 에이전트 전체를
돌리는 것이 아니다. 스킬이 하는 일만 본다.

샘플 고르는 법:

- 쉬운 것 하나 — 형식이 가장 반듯한 것
- 보통 둘 — 평소에 들어오는 것
- 예외 하나 이상 — 형식이 다르거나, 값이 빠졌거나, 표가 두 장으로 갈린 것

예외가 없으면 웹 앱이 실제로 겪을 일을 못 본다. 일부러 찾아 넣는다.

## 2. 산출물

샘플마다 `$LITE/runs/sample-k/` 폴더 하나(k 는 1부터):

- 입력 원본 파일(PDF·이미지·텍스트 등) 그대로 한 개 이상
- `output.json` — 그 샘플의 결과. 이름을 바꾸지 않는다

그리고 `$LITE/runs/run-1.md` 하나.

`output.json` 은 **최상위가 객체**여야 한다. 결과가 배열이면 `{ "items": [ … ] }` 처럼 감싼다.
게이트가 최상위 키로 판정하기 때문이다.

### 프롬프트 1 — 관찰 기록

```
방금 <스킬 이름> 스킬로 샘플 <N>건을 돌렸다. docs/agent-to-webapp-lite/runs/run-1.md 를 아래 네 절로 적어줘.
절 이름과 순서를 바꾸지 말 것.

## 수행한 단계
스킬이 실제로 한 일을 번호 목록으로. 문서에 적힌 절차가 아니라 이번에 한 일을 적는다.

## 판단이 필요했던 지점
규칙으로 딱 떨어지지 않아 판단한 곳. 무엇을 보고 어떻게 정했는지 한 줄씩.

## 예상과 달라서 방식을 바꾼 지점
샘플별로 다르게 처리해야 했던 곳. 없으면 '- 없음'.

## 샘플별 기록
표 하나로 적는다. 머리글은 이 줄 그대로:
| 샘플 | 입력 파일 | 사람 개입 |
사람 개입 칸에는 사람이 값을 고치거나 골라야 했던 것을 적는다. 없으면 '없음'.

각 샘플의 output.json 을 직접 읽고 적을 것.
```

## 3. 게이트

```
node $SKILL_DIR/scripts/check_lite.mjs 1
```

샘플 N건이 모두 폴더와 입력 파일과 `output.json` 을 갖췄는지, JSON 으로 읽히는지, run-1.md 에 네 절이
있는지 본다.

통과하면 2단계 문서를 읽는다.
