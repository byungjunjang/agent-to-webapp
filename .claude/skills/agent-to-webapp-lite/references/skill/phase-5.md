# 5단계 전환 (skill)

언제 읽나: phase-4 통과, phase-5 미통과.

## 1. brief.md 작성

`references/brief-template-skill.md` 를 `$LITE/brief.md` 로 복사하고 채운다. 헤딩은 고치지 않는다.

- `## 3층 구조`: 표 세 줄. 화면은 올리는 파일 종류·개수와 확인·수정 화면, 처리는 파싱 함수 하나와 LLM
  호출 수, 데이터는 결과 테이블과 입력 파일 크기. 샘플 최대 파일이 3MB 이상이면 데이터 줄에 `파일 크기`
  안내(상한 4.5MB, 넘을 때 문구)를 반드시 적는다
- `## 논의점`: 아래 "논의점 묻는 법" 대로. 답을 `결정:` 으로 적는다. 없으면 `- 없음`
- `## 1. 서버 쪽 호출`: skill-spec.md 의 `- 모델:` 값을 옮긴다
- `## 2. 실행 시간 분할`: 샘플별 걸린 시간과 `maxDuration = <초>`. 값을 안 적으면 배포 뒤 첫 실행에서
  끊긴다. 가장 오래 걸린 샘플의 2배쯤으로 하되 플랜 최대치 안에서
- `## 3. 상태 저장`: 첫 줄에 `Supabase` 또는 `DB 없음`. 확인·수정 화면이 있으면 고친 값과 확정 여부를
  남겨야 하므로 사실상 `Supabase` 다
- `## 4. 사람 확인 지점`: 판정이 `Claude 호출 유지` 면 `확인·수정 화면` 이 반드시 들어간다. `없음` 을
  쓸 수 없다(게이트가 실패시킨다). skill-spec.md 의 확신도 규칙을 화면 동작으로 옮긴다
- `## 5. 외부 서비스로 뺄 단계`: 없으면 `- 없음`
- `## 6. 인증`: 틀의 문장을 그대로 둔다. "범위 밖" 과 "Vercel 배포 보호를 켠다" 둘 다. 고정 규칙이다
- `## 7. 배포 후 검증`: 틀의 체크박스를 그대로 둔다

### 논의점 묻는 법

학습자는 비개발자다. 한 번에 하나씩, 상황 한 줄·선택지 둘·기본값과 이유로 묻는다. 조건이 안 걸리면
묻지 않는다. `--batch` 면 기본값으로 적고 `(기본값)` 을 붙인다.

1. 3절을 정할 때. "확인한 결과를 나중에 다시 열어 볼 일이 있나요? 있으면 저장소(Supabase)가 붙어 만들 게
   늘어납니다." 기본값: 있다. 확인·수정 화면이 있으면 상태를 남겨야 해서 사실상 정해져 있다
2. 밖으로 나가는 단계가 있을 때(발송·결제·외부 저장). "이 앱이 진짜로 보낼까요, 화면에 보여주고 사용자가
   복사하게 할까요? 데모라면 흉내가 안전합니다. 잘못 보내면 되돌릴 수 없어서요." 기본값: 흉내

화면 생김새(색·배치)는 묻지 않는다. 앱을 보기 전에 정하기 어렵다. 프롬프트 5 의 기본값으로 만들고 보고 고친다.

## 2. prompt.md 작성

아래 "프롬프트 5" 를 `$LITE/prompt.md` 에 남긴다. 5단계는 이 파일로 끝난다. 터미널에만 보여 주면
스크롤에 묻히고 다른 기기나 다음 날의 새 세션에서는 찾을 수 없다.

````
`$APP` 에서 새 세션을 열고 아래 블록을 그대로 붙여넣는다. 브리프: `docs/agent-to-webapp-lite/brief.md`

```
<프롬프트 5 원문>
```
````

### 프롬프트 5 — 스킬 이식

```
docs/agent-to-webapp-lite/brief.md 와 docs/agent-to-webapp-lite/skill-spec.md 를 읽고 이 스킬을 Next.js 웹 앱으로 만들어줘.
- 이 폴더에서 create-next-app 을 먼저 돌릴 것(TypeScript · Tailwind CSS · App Router · src/ 디렉터리). docs/ 와 .git 은 그대로 둔다
- 화면 컴포넌트는 shadcn/ui 로 만들 것. npx shadcn@latest init 을 돌리고 쓰는 컴포넌트만 add 한다. Tailwind 유틸리티 밖에서 CSS 를 따로 짜지 말 것
- skill-spec.md 의 입력·출력 스키마를 타입으로 그대로 옮기고, 파싱 함수는 src/lib/workflow/ 에 하나로 둘 것.
  프롬프트를 쓴다면 spec 의 원문·모델·최대 토큰·타임아웃을 그대로 쓴다
- Claude 를 부르는 코드와 API 키는 서버 쪽(Route Handler 또는 Server Action)에만 둘 것
- 파싱하는 Route Handler 에 export const maxDuration 을 브리프 2절의 값으로 둘 것. 기본 제한은 최대치보다 짧다
- 브리프의 "3층 구조" 표대로 둘 것. 화면은 src/app/, 처리는 src/lib/workflow/, 저장은 src/lib/data/
- 파일은 multipart 로 올릴 것(JSON 에 base64 로 담으면 1.33배 커진다). 상한을 넘으면 올리기 전에 거절 문구를 보여준다
- 브리프 "4. 사람 확인 지점" 의 확인·수정 화면을 만들 것. 파싱 결과를 표로 보여주고 고칠 수 있게 한 뒤 확정한다.
  확정 전에는 결과를 내보내지 않는다
- 로그인은 만들지 말 것. 단일 사용자 데모다. 배포 보호는 브리프 6절대로 Vercel 설정에서 켠다
```

바이브 코딩은 이 스킬의 범위 밖이다. 배포 후 확인은 브리프 7절의 체크리스트를 따른다.
