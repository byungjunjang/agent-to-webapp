# 4단계 재검증 (dashboard)

언제 읽나: phase-3 통과, phase-4 미통과.

## 1. 학습자 안내

에이전트를 **한 번 더** 돌린다. 같은 입력이 아니어도 된다 — 오히려 다른 날·다른 범위가 낫다. 실행 간에
출력이 흔들리는지 보는 것이 목적이다. 돌리고 나면 새 출력 산출물을 두고 돌아온다.

## 2. 산출물

- `$LITE/runs/run-2.schema.md` — 1단계와 **같은 일곱 절**. `## 출처` 와 `## 열` 을 포함해 형식이 같아야 대조가 된다
- `$LITE/verify/report.md` — 세 절

빠뜨리면 실패한다.

'없음' 이 아니면 게이트가 실패시킨다 — 키가 키 구실을 못 하는 것이다.

## 판정

## 3. 게이트

```
node $SKILL_DIR/scripts/check_lite.mjs 4
```

게이트가 직접 하는 일:

- 계약의 열이 run-2 에 없으면 **실패**(삭제)
- 계약의 열 타입이 run-1 과 run-2 에서 다르면 **실패**
- `## 키 중복` 이 `없음` 이 아니면 **실패**
- 게이트가 찾은 깨지는 열 이름이 report.md 본문에 없으면 **실패**
- 계약 밖의 새 열은 경고로만 알린다

통과하면 게이트가 STATUS 의 `verdict` 를 `조건부 고정 가능` → `고정 가능` 으로 확정하고 로그에 남긴다.
`rollback 3`·`rollback 4` 는 확정을 되돌린다.

## 4. 깨졌으면

- 계약을 새 현실에 맞추려면 `node $SKILL_DIR/scripts/check_lite.mjs rollback 3` 뒤 3단계부터
- 출력 자체가 고정되지 않는다고 보이면 `rollback 2` 로 판정부터 다시

에이전트를 고쳐 출력을 되돌리는 것도 답이다. 그때는 1단계부터 다시 관찰한다.
