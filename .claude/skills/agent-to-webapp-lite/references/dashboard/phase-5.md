# 5단계 전환 (dashboard)

언제 읽나: phase-4 통과, phase-5 미통과.

## 1. brief.md 작성

`references/brief-template-dashboard.md` 를 `$LITE/brief.md` 로 복사하고 채운다. 헤딩은 고치지 않는다.

- `## 3층 구조`: 표 세 줄. 화면은 표 한 화면과 필터와 갱신 배지, 처리는 조회·정렬·집계 함수,
  데이터는 계약의 테이블 이름. 제외 열은 select 에서 뺀다고 처리 줄에 적는다
- `## 논의점`: 아래 "논의점 묻는 법" 대로. 답을 `결정:` 으로 적는다. 없으면 `- 없음`
- `## 1. 데이터 계약 요약`: contract.md 의 테이블 이름과 유일 키를 **글자 그대로** 옮긴다(게이트가 대조한다)
- `## 2. 화면 목록`: 한 화면 원칙. 표 하나로 시작한다. 차트는 다음 세션이 보고 붙인다
- `## 3. 필터·정렬·집계`: 필터는 기간과 계약의 분류 열 하나면 충분하다
- `## 4. 갱신 표시`: `마지막 갱신 시각` 이라는 말이 반드시 들어간다. 오래됐을 때와 한 번도 안 돌았을 때의
  화면을 적는다. 에이전트가 멈춘 것을 화면이 숨기면 안 된다
- `## 5. 적재 경로`: 계약의 갱신 주체를 옮기고 Supabase 로 어떻게 넣는지 한 줄
- `## 6. 인증`: 틀의 문장을 그대로 둔다. "범위 밖" 과 "Vercel 배포 보호를 켠다" 둘 다. 고정 규칙이다
- `## 7. 배포 후 검증`: 틀의 체크박스를 그대로 둔다
- 제외 열 이름을 2·3절에 쓰지 않는다. 게이트가 그 이름을 찾으면 실패시킨다

### 논의점 묻는 법

학습자는 비개발자다. 한 번에 하나씩, 상황 한 줄·선택지 둘·기본값과 이유로 묻는다. 조건이 안 걸리면
묻지 않는다. `--batch` 면 기본값으로 적고 `(기본값)` 을 붙인다.

1. 계약에 제외 열이 있을 때. "민감한 열(<이름>)을 대시보드에서 빼면 <그 열로 보던 것>을 볼 수 없습니다.
   그래도 뺄까요?" 기본값: 뺀다. 빼지 않기로 하면 계약을 고쳐야 하므로 `rollback 3`
2. 계약의 행 수가 5000 이상일 때. "행이 <n>건입니다. 전부 불러오면 화면이 느립니다. 기간 필터를
   기본으로 걸까요?" 기본값: 최근 3개월. 답을 3절 필터의 기본값으로 적는다

화면 생김새(색·배치·차트 종류)는 묻지 않는다. 앱을 보기 전에 정하기 어렵다. 프롬프트 5 의 기본값으로
만들고 보고 고친다.

## 2. prompt.md 작성

아래 "프롬프트 5" 를 `$LITE/prompt.md` 에 남긴다. 5단계는 이 파일로 끝난다. 터미널에만 보여 주면
스크롤에 묻히고 다른 기기나 다음 날의 새 세션에서는 찾을 수 없다.

````
# 다음 세션 프롬프트: <이름>

`$APP` 에서 새 세션을 열고 아래 블록을 그대로 붙여넣는다. 브리프: `docs/agent-to-webapp-lite/brief.md`

```
<프롬프트 5 원문>
```
````

## 3. 게이트

```
node $SKILL_DIR/scripts/check_lite.mjs 5
```

일곱 절과 `## 3층 구조`·`## 논의점`, 4절의 `마지막 갱신 시각`, 6절의 `배포 보호`, 논의점 항목마다 `결정:`,
1절과 계약의 테이블·유일 키 일치, 제외 열이 2·3절에 없는지, prompt.md 코드 블록의 고정 문자열을 본다.

## 4. 다음 세션

통과하면 학습자에게 아래를 보여주고 prompt.md 의 코드 블록을 그대로 붙인 뒤 끝낸다.

```
5단계 통과. 이제 $APP 에서 새 세션을 열고 docs/agent-to-webapp-lite/prompt.md 의 블록을 붙여넣으세요.
```

### 프롬프트 5 — 대시보드 만들기

```
docs/agent-to-webapp-lite/brief.md 와 docs/agent-to-webapp-lite/contract.md 를 읽고 이 데이터를 보는 대시보드를 Next.js 로 만들어줘.
- 이 폴더에서 create-next-app 을 먼저 돌릴 것. docs/ 와 .git 은 그대로 둔다
- 저장소는 Supabase 를 쓴다. contract.md 의 테이블·열·타입·유일 키 그대로 테이블을 만들고, 같은 키면 덮어쓰는 upsert 로 둔다
- 브리프의 "3층 구조" 표대로 둘 것. 화면은 src/app/, 조회·집계는 src/lib/query/, 저장은 src/lib/data/.
  화면 파일에서 DB 를 직접 부르지 말 것
- contract.md 의 "제외 열" 은 select 에서 빼고 화면·응답 어디에도 내보내지 말 것
- 화면은 표 하나로 시작한다. 브리프 "3. 필터·정렬·집계" 의 필터와 정렬을 붙이고, 머리에 마지막 갱신 시각을 띄운다
- 에이전트가 안 돌아 데이터가 오래됐거나 비었을 때 보이는 화면을 브리프 "4. 갱신 표시" 대로 만들 것
- 로그인은 만들지 말 것. 단일 사용자 데모다. 배포 보호는 브리프 6절대로 Vercel 설정에서 켠다
- 에이전트 쪽에 붙일 적재 코드는 브리프 "5. 적재 경로" 대로 따로 만들어 둘 것(웹 앱은 읽기만 한다)
```

바이브 코딩은 이 스킬의 범위 밖이다. 배포 후 확인은 브리프 7절의 체크리스트를 따른다.
