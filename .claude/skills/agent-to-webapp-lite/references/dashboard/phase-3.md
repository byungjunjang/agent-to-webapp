# 3단계 고정 (dashboard)

언제 읽나: phase-2 통과, phase-3 미통과.

## 1. 데이터 계약을 쓴다

산출물은 `$LITE/contract.md` 하나다. 이것이 에이전트와 웹 앱 사이의 계약이다 — 에이전트는 이 모양으로 넣고,
웹 앱은 이 모양으로 읽는다. 다음 세션이 Supabase 테이블을 이 문서대로 만든다.

### 프롬프트 3 — 계약 쓰기

```
docs/agent-to-webapp-lite/runs/run-1.schema.md 와 verdict.md 를 읽고
docs/agent-to-webapp-lite/contract.md 를 아래 아홉 절로 써줘. 절 이름과 순서를 바꾸지 말 것.

## 테이블
Supabase 테이블 이름 하나. 영문 소문자 스네이크케이스(예: channel_sales).

## 열
| 열 | 타입 | 필수 | 설명 |
머리글을 이 줄 그대로 쓴다. 관찰(run-1.schema.md)에 없는 열을 만들지 말 것 — 게이트가 실패시킨다.
대시보드에 필요 없는 열은 여기서 빼도 된다. 타입은 관찰의 타입을 따른다.

## 유일 키
행 하나를 가리키는 열 또는 열 조합. '없음' 을 쓸 수 없다. 키가 없으면 여기서 멈추고
에이전트 출력에 키를 만든 뒤 1단계부터 다시 한다.

## 갱신 시각
언제 채워졌는지 알려주는 열 이름. 관찰에 없으면 에이전트가 마지막 단계에서 넣을 열 이름을 정한다.

## upsert 규칙
같은 키가 오면 어떻게 할지. 기본은 '같은 키면 덮어쓴다'.

## 갱신 주체
누가 언제 넣는가. 에이전트의 어느 단계인지 사람 말로 한 줄.

## 제외 열
대시보드에 싣지 않을 민감 열 이름. verdict.md 의 '## 민감 열' 을 옮긴다. 없으면 '- 없음'.
한 줄에 하나, '- 열 이름' 또는 '- 열 이름 — 사유'. 이름은 관찰의 열 이름 그대로(띄어쓰기·하이픈 포함).
여기 적은 이름은 5단계 브리프의 화면·필터 절에 나타나면 안 된다(게이트가 대조한다).

## 파생 집계
합계·평균처럼 미리 계산해 둘 것. 없으면 '- 없음'. 화면에서 계산해도 되면 여기 적지 않는다.

## 에이전트에 추가할 마지막 단계
에이전트가 출력 파일을 만든 뒤 무엇을 더 해야 하는지 사람 말로 한두 줄
(예: "CSV 를 읽어 channel_sales 에 channel+sold_on 키로 upsert 한다").
```

## 2. 게이트

```
node $SKILL_DIR/scripts/check_lite.mjs 3
```

아홉 절이 차 있는지, 유일 키가 `없음` 이 아닌지, 계약의 열이 관찰된 열 안에 있는지 본다.
유일 키·제외 열·갱신 주체 세 항목은 비면 실패한다.

검사가 통과하면 학습자에게 `contract.md` 를 보여주고 동의를 받는다. 동의하면:

```
node $SKILL_DIR/scripts/check_lite.mjs 3 --approve
```

판정을 다시 해야겠으면 `node $SKILL_DIR/scripts/check_lite.mjs rollback 2`.

## 3. 학습자에게 설명할 것

계약은 두 쪽을 묶는다. 이 뒤로 에이전트 출력이 바뀌면 대시보드가 깨진다 — 4단계가 그것을 한 번 확인한다.
민감 열을 뺀다는 것은 「화면에 안 보인다」가 아니라 「테이블에서 select 하지 않는다」는 뜻이다.
