- 실행: 2026-09-11, `verify/run.ts` 를 `workflow.md` 순서(단계 1–12)대로. 입력 3개를 포그라운드에서 하나씩 돌렸다

## 모델

claude-sonnet-5 (`A2W_MODEL` 미설정, 기본값. API 응답의 `model` 도 `claude-sonnet-5`). 로컬 에이전트 세 실행의 모델은 기록에 없다(훅 기록은 도구 호출만 남긴다). 그래서 LLM 단계(2·5·8·9)의 판단 차이는 모델 차이일 수도 있다.

## 재검증 중 고친 것 (workflow.md 반영 필요)

이 세 가지는 verify/ 코드에만 고쳤다. 단계의 입출력 스키마는 workflow.md 그대로이고, 바뀐 것은 LLM 도구 스키마·프롬프트 초안·후처리 한 줄이다. 5단계 전환 때 workflow.md 의 단계 5·9 프롬프트 초안을 이 내용으로 갱신해야 한다. 고치기 전 파일은 `out/*.before-fix.ts.txt`.

1. **단계 5 도구 스키마** (`steps/05-missing-specs.ts`). 두 목록(missing_specs, checklist_defined)을 LLM 이 따로 내게 하니 같은 key 가 양쪽에 들어가는 자기모순이 났다(입력 2 시도 1·2, 재시도 포함 4회 중 4회). 지금은 여섯 key 마다 `{ key, defined, evidence, item_name, item_name_en, reason, assumption }` 판정 하나를 받고, 코드가 `defined` 로 두 목록에 나눈다. "합쳐 정확히 한 번" 이 구조로 보장된다. 고친 뒤 3회 실행(입력 2 시도 3·4, 입력 3, 입력 1 재실행) 모두 통과. 프롬프트 초안은 "여섯 key 마다 판정 하나씩, 정확히 여섯 개" 로 바꿨다
2. **단계 9 첨부 파일명 자리표시자** (`steps/09-write-emails.ts`). 한글 파일명 `견적서_….xlsx` 를 중국어 본문에서 모델이 `见积서_…` 로 변형했다(입력 2 시도 3, 재작성에서도). 로컬 run-3 도 "见积书" 로 썼다가 손으로 고쳤다. 지금은 프롬프트 10번이 `[[ATTACHMENT]]` 자리표시자만 쓰게 하고 코드가 `xlsx_filename` 으로 바꾼다. 단계 11 의 파일명 검사는 그대로다. 재시도 안내도 파일명 대신 자리표시자를 쓰라고 한다
3. **도구 input 문자열 풀기** (`lib/llm.ts` `unwrapStringified`). 모델이 도구 input 을 `{"<키>": "<JSON 문자열>"}` 로 감싼 경우(입력 2 시도 2), 필수 키가 다 있는 JSON 문자열을 찾아 푼다. usage 에 note 로 남긴다

발견했지만 고치지 않은 것. workflow.md 에서 정할 일이다.

4. 단계 5 재시도 사유가 기록에 남지 않는다(입력 2 시도 4). 웹 앱에서는 재시도 피드백을 작업 로그에 남겨야 원인을 볼 수 있다
5. 단계 9 프롬프트가 `references.not_suitable_routes` 를 이메일에 쓰지 말라고 하지 않아 입력 1·2 이메일에 질화 참고 단가(23.41 / 22.49)가 들어갔다. 단계 9 입력에서 그 배열을 빼거나 프롬프트에 금지 문장을 넣는다
6. 단계 2 가 `annual_volume` 을 월 물량×12 로 계산해 넣는다(입력 1·2). 프롬프트 "값을 지어내지 않는다" 와 어긋난다. 계산 필드는 코드가 하거나 "계산하지 않는다" 를 명시한다

## 사람이 봤어야 할 것

재검증 스크립트는 사람 단계 두 곳을 자동 승인했다.

- **단계 4 견적 전제 확인 (입력 3)**: `lot_size 1000`, `delivery_days 12`, `material SCM420H` 를 스크립트가 넣었다. 실제 앱에서는 영업 담당이 넣는다. 수량은 기본값 없이 빈 칸이어야 한다(219 pcs 12.76 / 500 pcs 16.63 / 1,000 pcs 13.92 로 단가가 크게 움직인다). 입력 1·2 는 mode firm 이라 `skipped`
- **단계 12 발송 전 검토 (세 입력)**: 자동 승인. 확인 목록은 workflow.md 단계 12 의 네 가지(headline 루트·단가, 대안 설명, 누락 스펙 가정 문구가 이 도면에 맞는지, provisional 가정 표시 세 곳, 이메일 호칭·톤·요청 항목 회신)

사람이 봤다면 잡았을 것:

1. **`hardness_test` 판정 흔들림.** 같은 입력 1 에서 첫 실행은 누락, 재실행은 defined. 입력 2·3 도 defined. 로컬은 세 번 모두 누락. 도면 Note 3–5 에 값과 구간(C·D)은 있지만 측정 방법(단면 절단, HRC 직접/HV 환산)은 없다. 어느 쪽으로 볼지는 영업기술이 정해 규칙(프롬프트)에 적어야 한다. 그 전까지는 이 판정을 사람이 본다
2. **입력 3 마스킹 가정 방향.** "마스킹 없음, 전체 침탄" 은 입력 1·2 와 로컬 세 실행("나사부 방탄")과 반대다. 원가와 공정이 바뀌는 가정이다
3. **입력 2 호칭.** "Dear Ms. Maria Keller", "女士" 는 성별 추정이다
4. **입력 1·2 이메일의 질화 참고 단가.** 견적 대상이 아닌 루트의 단가가 고객에게 나간다
5. **입력 3 이메일의 RFQ 번호 표기.** 내부 번호 `INT-260911-5447` 이 "귀사의 RFQ No." 로 나간다. xlsx 는 "(당사 부여)" 로 표시했다
6. **`annual_volume` 계산값.** 문서에 없는 43,200 / 60,000 이 JSON 에 있다. 출처는 internal 로 표시돼 있다
7. **입력 2 확인 요청 항목 수.** `hardness_test` 가 defined 로 되면서 고객에게 측정 방법을 묻지 않게 됐다. 로컬은 물었다
