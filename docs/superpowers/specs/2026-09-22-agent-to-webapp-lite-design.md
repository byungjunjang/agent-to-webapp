# 설계: agent-to-webapp-lite 스킬 — 출력 한 벌·스킬 하나를 웹으로 옮기는 고정 공정

작성 2026-09-22. 출처 핸드오프: `.consulting-projects/celimax-claude-code-workshop/output/agent-to-webapp-lite-handoff.md`.
정식 스킬 기획서: `2026-09-11-agent-to-webapp-design.md`. 이 문서의 §2 가 lite 의 정본이다.

## 1. 배경과 목적

정식 `agent-to-webapp` 은 「모델이 정하던 순서를 코드로 고정할 수 있는가」를 묻는다. 에이전트 전체가 웹으로
옮겨간다는 전제다. 워크숍의 두 갈래는 그 전제를 만족하지 않는다.

- **A(대시보드)**: 에이전트는 계속 로컬에서 돈다. 웹은 에이전트가 남긴 출력만 읽는다. 순서가 웹으로
  옮겨가지 않으므로 고정할 순서가 없다. 옮겨가는 단위는 **출력 데이터**다.
- **D(입력 폼 앱)**: 파일을 올리면 서버가 파싱·판정한다. 에이전트의 스킬 하나만 서버 함수가 된다.
  옮겨가는 단위는 **스킬 하나**다.

두 경우 모두 같은 질문 구조(관찰 → 판정 → 고정 → 재검증 → 전환)를 쓰지만 고정하는 대상이 다르다.
정식 스킬에 `--lite` 를 얹으면 phase 문서·게이트 상수·테스트가 두 갈래로 갈라져 「스킬 하나 = 고정 공정
하나」가 깨진다. 형제 스킬을 새로 만든다.

## 2. 결정 사항

| # | 항목 | 결정 | 근거 |
|---|---|---|---|
| 1 | 스킬 수 | **스킬 하나** `agent-to-webapp-lite`. 모드는 `--mode dashboard\|skill` | 공정·STATUS·init/status/rollback·승인 게이트·5단계 prompt.md 가 모드와 무관하게 같다. 두 스킬이면 이 뼈대를 통째로 복제한다. 모드 차이는 `references/<mode>/` 와 게이트 분기 하나로 격리된다 (열린 항목 §10-1 닫음) |
| 2 | 위치 | 정본 `.claude/skills/agent-to-webapp-lite/`, 설치 `~/.claude/skills/agent-to-webapp-lite/` | 정식 스킬과 같은 규칙(정식 §2-2) |
| 3 | 실행 위치 | 에이전트 폴더의 형제 작업 폴더 `<이름>-app/`. 산출물은 `$APP/docs/agent-to-webapp-lite/` | 대상 안에서 부르면 대상 CLAUDE.md 가 세션을 오염시킨다(정식 §2-3). 폴더 이름을 정식과 다르게 두어 한 작업 폴더에서 둘을 섞어 돌려도 STATUS 가 충돌하지 않는다 |
| 4 | 호출 | `/agent-to-webapp-lite <에이전트 경로> --mode dashboard\|skill [--output <경로>] [--skill <이름>] [--samples N] [--batch]` | dashboard 는 읽을 출력 경로가, skill 은 옮길 스킬 이름과 샘플 수가 있어야 시작한다 |
| 5 | API 키 | **쓰지 않는다.** 관찰과 재검증은 학습자가 자기 세션에서 돌리고 스킬은 산출물만 읽는다. 정식의 `key` 명령과 `assets/verify-template` 러너를 가져오지 않는다 | 워크숍은 수동으로 충분하다. 키를 쓰면 설치 부담(.env)과 과금 설명이 두 스킬에 다 붙는다 (§10-3 닫음) |

| 7 | STATUS | lite 는 **자기 `status.mjs`** 를 갖는다. 정식 `status.mjs` 는 건드리지 않는다 | 필드가 다르다(`mode`·`output`·`skill`·`samples` vs `runtime`·`runs`·`model`). 상수 하나 문제가 아니라 내용이 달라 파라미터화보다 분리가 싸다. 정식 테스트는 한 줄도 바뀌지 않는다 (§10-5 닫음) |

| 9 | 승인 | 2·3단계는 `--approve` 없이 기록하지 않는다. `--batch` 면 질문 없이 넘긴다. `--override "<사유>"` 는 사람이 판정을 뒤집을 때만 | 정식 §2-7·§2-12 |
| 10 | 증거 우선 | 게이트가 **문서의 글이 아니라 산출물 자체를 파싱**해 판정한다: dashboard 4단계는 run-1·run-2 스키마의 열 표를 직접 대조하고, skill 2·3·4단계는 샘플 출력 JSON 의 키 집합을 직접 계산한다 | 정식 §2-26·§2-28 이 뒤늦게 막은 구멍(돌리지 않고 보고서만 써도 통과)을 처음부터 막는다 |
| 11 | dashboard 판정 등급 | 2단계는 관찰 1회 위에서 내리므로 `고정 가능` 을 거부하고 `조건부 고정 가능` 까지만 받는다. 4단계 재검증이 확정한다 | 정식 §2-22 와 같은 논리(실행 간 차이를 못 본 판정은 잠정이다) |
| 12 | 민감 열 | 계약의 `## 제외 열` 은 필수 항목이고, 5단계 게이트가 **제외 열 이름이 브리프의 화면·필터 절에 나타나면 실패**시킨다 | 이 모드의 진짜 사고는 계좌·급여·상담 원문·개인 이름이 대시보드에 실리는 것이다. 문장으로 다짐받는 대신 이름으로 대조한다 |
| 13 | 유일 키 | dashboard 3단계는 `## 유일 키` 가 비거나 `없음` 이면 실패한다 | 키 없이 upsert 가 없다. 키가 없으면 대시보드가 실행마다 중복 적재된다. 키를 못 찾으면 에이전트 출력을 먼저 고쳐야 한다 |
| 14 | skill 판정 어휘 | `코드로 고정` / `Claude 호출 유지` / `고정 불가`. dashboard 는 정식과 같은 `고정 가능` / `조건부 고정 가능` / `고정 불가` | skill 모드의 판정은 "고정되는가" 가 아니라 "무엇으로 고정하는가" 다. Claude 호출을 남기는 것도 고정(프롬프트·스키마·모델을 못 박는다)이다 |
| 15 | skill 사람 확인 | 판정이 `Claude 호출 유지` 면 브리프 4절에 `확인·수정 화면` 이 있어야 통과한다. `없음` 을 허용하지 않는다 | LLM 파싱 결과를 사람 확인 없이 확정하면 틀린 값이 그대로 남는다. 인보이스 금액·수량이 그 예다 |
| 16 | skill 재검증 | 학습자가 고정한 프롬프트·규칙으로 샘플 N건을 다시 돌려 `verify/sample-k.json` 에 둔다. 게이트는 파일 존재·JSON 파싱·**스펙 출력 스키마 키 충족**을 강제하고, 값 차이는 학습자 판단으로 둔다 | 스키마는 코드가 볼 수 있고 값은 볼 수 없다. 스키마 불일치는 웹 앱이 깨지는 문제라 게이트, 값 차이는 품질 문제라 사람 |
| 17 | 구글 시트 | CSV 로 내보낸 파일 경로만 받는다. `gws` 같은 외부 CLI 에 의존하지 않는다 | 설치 부담을 늘리지 않는다 (§10-4 닫음) |
| 18 | 브리프 절 | dashboard: `3층 구조`·`논의점`·`1 데이터 계약 요약`~`7 배포 후 검증`. skill: 정식 템플릿의 1·2·3·4·6·7 을 그대로, 5(외부 서비스)는 `- 없음` 허용 | dashboard 는 서버에서 Claude 를 부르지 않으므로 정식 1·2 절이 빈다. 대신 갱신 표시와 적재 경로가 필요하다 |
| 19 | 배포 보호 | 두 모드 모두 6절에 `배포 보호` 가 없으면 실패. 논의하지 않는 고정 규칙 | 정식 §2-27 과 같은 이유이고 dashboard 는 더 무겁다 — 노출되는 것이 실행 권한이 아니라 데이터다 |
| 20 | 3층 구조·논의점 | 두 모드의 브리프 맨 앞에 정식과 같은 `## 3층 구조` 표와 `## 논의점`(조건 걸릴 때만 최대 둘, 답은 `결정:`) | 정식 §2-27. 학습자가 자기 앱을 같은 틀로 본다 |
| 21 | 다음 세션 프롬프트 | 5단계는 `$LITE/prompt.md` 에 코드 블록으로 남긴다. 게이트가 모드별 `PROMPT_MUST` 를 확인한다. 스타터 저장소를 전제하지 않고 `create-next-app` 부터 시작한다 | 정식 §2-24 |
| 22 | 설치 | `install.mjs` 가 `.claude/skills/` 아래 스킬을 모두 훑어 각각 `~/.claude/skills/<이름>/` 에 설치한다. `install(src, dest)` 시그니처와 `.env` 보존 규칙은 그대로 두고 `installAll` 을 얹는다 | 스킬이 둘이 되면 설치 절차가 둘로 갈라진다. 기존 테스트가 한 줄도 바뀌지 않는 범위에서 얹는다 |
| 23 | 언어 | 학습자에게는 한국어. 학습자가 다른 언어로 쓰면 그 언어로 | 정식과 같다 |
| 24 | 대상 무변경 | `$TARGET` 의 git 추적 파일을 건드리지 않는다. 훅도 설치하지 않는다 | lite 관찰은 도구 호출 기록이 필요 없다. dashboard 는 출력 파일만, skill 은 샘플 입출력만 본다 |

## 3. 용어

- `$APP`: 지금 열린 작업 폴더 `<이름>-app/`. 나중에 웹 앱 repo 가 된다
- `$LITE`: `$APP/docs/agent-to-webapp-lite`. 산출물은 전부 여기
- `$TARGET`: 대상 에이전트 폴더. STATUS 의 `target`
- `$OUTPUT`: dashboard 모드에서 에이전트가 남기는 출력 산출물 경로. STATUS 의 `output`
- `$SKILL`·`$SAMPLES`: skill 모드에서 옮길 스킬 이름과 샘플 수(기본 5). STATUS 의 `skill`·`samples`

## 4. STATUS

`$LITE/STATUS.md`. 게이트 스크립트만 쓴다.

```
# agent-to-webapp-lite STATUS

target: ../channel-sales-check
mode: dashboard
output: ../channel-sales-check/out/sales.csv
created: 2026-09-22
phase-1: passed 2026-09-22
phase-2: passed 2026-09-22 approved
phase-3:
phase-4:
phase-5:

## log
- 2026-09-22 init
```

`mode: skill` 이면 `output` 대신 `skill:`·`samples:` 줄이 온다. 파서는 없는 줄을 기본값으로 견딘다.

## 5. dashboard 모드

에이전트가 시트·CSV·JSON·xlsx 를 남기고 웹은 그것을 읽기만 한다.

| 단계 | 학습자 | 산출물 | 게이트가 보는 것 |
|---|---|---|---|
| init | 에이전트 경로와 출력 산출물 경로 | STATUS | `--target` 존재. `--output` 은 기록만(1단계 전에는 없을 수 있다) |
| 1 관찰 | 에이전트를 1회 실행 | `runs/run-1.schema.md` | 일곱 절 존재·비지 않음, `## 열` 표에 행 1개 이상 |
| 2 판정 | verdict 읽고 동의 | `verdict.md` | 마지막 `판정:` 줄, `## 근거`·`## 민감 열` 절. `고정 가능` 거부(§2-11) |
| 3 고정 | contract 읽고 동의 | `contract.md` | 아홉 절. 유일 키·제외 열·갱신 주체 필수, 유일 키 `없음` 불가. 계약 열이 관찰 열에 다 있는지 대조 |
| 4 재검증 | 에이전트를 한 번 더 실행 | `runs/run-2.schema.md`, `verify/report.md` | 게이트가 열 표를 직접 대조한다(아래) |
| 5 전환 | 논의점에 답 | `brief.md`, `prompt.md` | 아홉 절, 제외 열 교차 검사, 고정 문자열 |

### 5-1. `run-N.schema.md` 의 절

```
## 출처            파일·시트 이름과 경로
## 열              | 열 | 타입 | 예시값 | 빈 값 비율 |
## 행 수
## 유일 키 후보     열 조합. 없으면 '없음'
## 갱신 시각 열     열 이름. 없으면 '없음'
## LLM 문장 열      목록. 없으면 '- 없음'
## 민감 열 후보     계좌·급여·원문·개인 이름. 없으면 '- 없음'
```

run-1 과 run-2 가 같은 절을 쓴다. 4단계 대조가 성립하는 이유다.

### 5-2. 4단계 대조 (게이트가 계산한다)

게이트가 run-1·run-2 의 `## 열` 표를 파싱해 계약과 대 본다.

- **실패** — 계약에 있는 열이 run-2 에 없다(삭제)
- **실패** — 계약에 있는 열의 타입이 run-1 과 run-2 에서 다르다
- **실패** — `verify/report.md` 의 `## 키 중복` 절이 `없음` 이 아니다
- **실패** — 게이트가 찾은 깨지는 열 이름이 `verify/report.md` 본문에 없다(보고서가 실제를 안 적었다)
- **경고** — run-2 에만 있는 새 열(계약 밖이라 무시해도 된다)

실패하면 `rollback 3`(계약을 고친다) 또는 `rollback 2`(판정부터 다시)를 안내한다.

`verify/report.md` 의 절: `## 스키마 diff` · `## 키 중복` · `## 판정`.

### 5-3. `contract.md` 의 절

`## 테이블` · `## 열`(`| 열 | 타입 | 필수 | 설명 |`) · `## 유일 키` · `## 갱신 시각` · `## upsert 규칙` ·
`## 갱신 주체` · `## 제외 열` · `## 파생 집계` · `## 에이전트에 추가할 마지막 단계`.

### 5-4. 브리프 절과 고정 문자열

```
## 3층 구조        표 세 줄: 화면(프리젠테이션)·처리(비즈니스)·데이터(저장·바깥)
## 논의점          항목마다 '결정:'. 없으면 '- 없음'
## 1. 데이터 계약 요약   테이블 이름과 유일 키가 계약과 같아야 한다
## 2. 화면 목록          한 화면 원칙
## 3. 필터·정렬·집계
## 4. 갱신 표시          '마지막 갱신 시각' 필수. 에이전트가 안 돌면 어떻게 보이는지
## 5. 적재 경로          에이전트의 마지막 단계가 어떻게 넣는가
## 6. 인증               '배포 보호' 필수
## 7. 배포 후 검증        체크박스 다섯 이상
```

교차 검사: `contract.md` 의 제외 열 이름이 `## 2. 화면 목록` 또는 `## 3. 필터·정렬·집계` 에 나타나면 실패.

논의점(조건 걸릴 때만, 최대 둘):
1. 제외 열이 있을 때 — "민감한 열을 빼면 …를 볼 수 없습니다. 그래도 뺄까요?" 기본값: 뺀다
2. 행 수가 많을 때 — "행이 n건입니다. 기간 필터를 기본으로 걸까요?" 기본값: 최근 3개월

`PROMPT_MUST`: `docs/agent-to-webapp-lite/brief.md` · `docs/agent-to-webapp-lite/contract.md` ·
`create-next-app` · `Supabase` · `3층 구조` · `src/lib/data/`.

## 6. skill 모드

파일을 올리면 서버가 파싱·판정한다. 에이전트의 스킬 하나가 서버 함수가 된다.

| 단계 | 학습자 | 산출물 | 게이트가 보는 것 |
|---|---|---|---|
| init | 에이전트 경로, 스킬 이름, 샘플 수 | STATUS | `--target` 존재, `--skill` 필요, `--samples` ≥ 1(기본 5) |
| 1 관찰 | 샘플 N건에 그 스킬 실행 | `runs/sample-k/`(입력 + `output.json`), `runs/run-1.md` | 샘플 N개 모두 `output.json` 존재·JSON 파싱. run-1.md 네 절 |
| 2 판정 | verdict 읽고 동의 | `verdict.md` | 마지막 `판정:` 줄. 샘플 키 집합이 서로 다르면 `코드로 고정` 거부 |
| 3 고정 | spec 읽고 동의 | `skill-spec.md` | 입출력 JSON 블록, 판정별 필수 절, 출력 스키마가 공통 샘플 키를 덮는가 |
| 4 재검증 | 고정한 것으로 샘플 N건 재실행 | `verify/sample-k.json`, `verify/report.md` | N건 존재·파싱·출력 스키마 키 충족. 값 차이는 notes |
| 5 전환 | 논의점에 답 | `brief.md`, `prompt.md` | 아홉 절, 고정 문자열, 샘플 파일 크기 |

### 6-1. `run-1.md` 의 절

정식 1단계의 세 헤딩을 그대로 쓴다: `## 수행한 단계` · `## 판단이 필요했던 지점` ·
`## 예상과 달라서 방식을 바꾼 지점`. 여기에 `## 샘플별 기록`(`| 샘플 | 입력 파일 | 사람 개입 |`)을 더한다.

### 6-2. 판정과 근거

`판정: 코드로 고정` / `판정: Claude 호출 유지` / `판정: 고정 불가`. 절은 `## 근거`(decision-axes 의 세 축을
그대로 적용) · `## 출력 구조` · `## 사람 확인`.

게이트가 `runs/sample-*/output.json` 의 최상위 키 집합을 계산한다. 샘플마다 키가 다르면 `코드로 고정` 을
거부한다 — 규칙으로 쓸 수 있다는 주장이 관찰과 어긋나기 때문이다.

`고정 불가` 면 종료하고 라우팅을 안내한다: 시각·OCR 이 필요하거나 실행이 길면 이 스킬의 대상이 아니다.

### 6-3. `skill-spec.md` 의 절

`## 입력 스키마`(다음 줄에 json 코드 블록) · `## 출력 스키마`(같음) · `## 사람 확인`(확신도와 규칙) ·
`## 실패 처리`. 판정이 `코드로 고정` 이면 `## 규칙`(목록 1개 이상), `Claude 호출 유지` 면
`## 프롬프트`(코드 블록)와 `- 모델:` · `- 최대 토큰:` · `- 타임아웃:`.

게이트: 출력 스키마 JSON 의 최상위 키가 모든 샘플에 공통인 키를 덮지 못하면 실패(관찰된 것을 스펙이 빠뜨렸다).

### 6-4. 브리프 절과 고정 문자열

정식 템플릿의 일곱 절을 그대로 쓴다(`1. 서버 쪽 호출` ~ `7. 배포 후 검증`) + `## 3층 구조` · `## 논의점`.

- 2절: `maxDuration` 필수
- 3절: 첫 줄에 `Supabase` 또는 `DB 없음`. 확인·수정 화면이 있으면 상태를 남겨야 하므로 사실상 Supabase
- 4절: 판정이 `Claude 호출 유지` 면 `확인·수정 화면` 필수, `없음` 불가(§2-15)
- 5절: `- 없음` 허용
- 6절: `배포 보호` 필수
- 샘플 최대 파일이 3MB 이상이면 브리프에 `파일 크기` 안내 필수(정식 §2-27 과 같은 상한 4.5MB)

`PROMPT_MUST`: `docs/agent-to-webapp-lite/brief.md` · `docs/agent-to-webapp-lite/skill-spec.md` ·
`create-next-app` · `src/lib/workflow/` · `3층 구조` · `maxDuration`.

## 7. 파일 구조

```
.claude/skills/agent-to-webapp-lite/
  SKILL.md
  references/
    dashboard/phase-1.md … phase-5.md
    skill/phase-1.md … phase-5.md
    brief-template-dashboard.md
    brief-template-skill.md
    decision-axes.md              # 정식 스킬에서 복사. 동일성 테스트
  scripts/
    check_lite.mjs
    lib/status.mjs  md.mjs(복사)  schema.mjs  phase1.mjs … phase5.mjs
tests/
  lite_cli.test.mjs  lite_status.test.mjs  lite_schema.test.mjs
  lite_phase1.test.mjs … lite_phase5.test.mjs
  lite_references.test.mjs  lite_skill_md.test.mjs  lite_shared.test.mjs
```

`schema.mjs`: 열 표 파싱, 열 diff, JSON 키 집합 계산. 두 모드의 증거 검사가 여기 모인다.
`phaseN.mjs`: `checkPhaseN(liteDir, { mode, … })` 하나가 모드로 분기한다. 헤딩·필드 문자열은 이 파일들의
상수이고 `lite_references.test.mjs` 가 references 문서와 대조한다.

phase 문서는 정식처럼 자기 프롬프트를 안에 담고, 게이트가 찾는 고정 문자열이 그 프롬프트에 들어 있어야 한다.

## 8. 정식 스킬과의 관계

- **복사**: `md.mjs`, `decision-axes.md` (§2-6)
- **형식만 빌림**: `status.mjs`(필드가 다르다), `port-brief-template.md`(skill 모드 브리프의 일곱 절),
  phase-5 의 prompt.md 구조, 1단계 세 헤딩
- **가져오지 않음**: `assets/verify-template`, `key.mjs`, `models.mjs`, `log_tool_use.mjs`, 훅 자산
- 정식 스킬의 파일은 `install.mjs` 외에 바뀌지 않는다. 정식 테스트도 바뀌지 않는다

## 9. 테스트

`node --test "tests/*.test.mjs"` 가 두 스킬을 함께 돌린다.

- `lite_status`: 왕복, 모드별 필드, 없는 줄 기본값, CRLF
- `lite_schema`: 열 표 파싱, diff(추가·삭제·타입 변경), JSON 키 집합·교집합
- `lite_phase1..5`: 모드마다 통과 1건 + 실패 분기마다 1건
- `lite_cli`: init 유효성(모드별 필수 인자), 승인 게이트, `--batch`, `--override`, rollback, 종료코드
- `lite_references`: phase 문서·브리프 틀이 게이트 상수 문자열을 담는가
- `lite_shared`: 복사한 두 파일이 정식 원본과 바이트 동일한가
- `lite_skill_md`: frontmatter, 줄 수, 참조 경로 실재

## 11. dogfood (저장소 밖)

## 12. 열린 항목

- dashboard 1단계에서 xlsx 를 학습자가 어떻게 요약하는가. 현재 안은 에이전트 세션이 읽고 절을 채우는 것이고
  스킬은 파일을 직접 파싱하지 않는다. dogfood 에서 CSV 외 형식이 걸리면 다시 본다
- 열 타입 어휘(`문자열`·`정수`·`실수`·`날짜`·`불리언`)를 고정 목록으로 강제할지. 지금은 자유 문자열이고
  4단계 대조는 문자열 일치로 본다. 표기 흔들림이 거짓 실패를 내면 목록으로 좁힌다
- skill 모드 4단계에 정식 verify-template 러너(API 키)를 선택 옵션으로 붙일지. 워크숍은 수동으로 충분하다(§2-5)
- 두 스킬을 한 작업 폴더에서 이어 쓰는 경로(대시보드를 만든 뒤 에이전트 전체를 옮기는 경우)는 dogfood 밖이다
